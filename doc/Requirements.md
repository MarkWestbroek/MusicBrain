I am already planning and thinking about a few projects for years that have a lot in common.

Commonalities:
- they are about making music
- they involve controllers, a brain that processes these control signals and output to several devices

The different concrete subprojects are:

## 1 a simple effect-box switcher
A typical guitarist owns a lot of effect pedals. They can be daisy chained and usually every pedal has an on off switch that bypasses the pedal or effecuates it. Still, that makes the signal path long and often noisy.

An often used solution is to make a compact signal path via relays that breaks out to the several pedals in and out. The relays are default on = bypass the pedal. A configuration manager allows the guitarist to choose one of a number of configured programs (or 'patches' in synth terms) that switches the desired pedals on. The result is much more noise free signal: only the desired pedals are involved, without unnessesary cables, plugs and sockets, through which the signal goes.

The basic version is a simple chain of relays, no branches or parallel paths, and the more complicated involves for example a few different types of delay or reverb, usually in the end, that merge their signals via a basic mixer.

### configuration
The guitarist needs to configure his or her concrete hardware setup in the controller.

That is a question: how to do that?
- Use a computer and sync that setup to the controller.
- use a simple (90-ies) LED textscreen (eg 32 characters in 2 lines) and a couple of buttons right on the controller
- use a more fancy touch-screen
- use phone or tablet app
- a combination of the above

The configuration has two aspects:
- what is the current hardware setup?
- what are the programs? (Each program bypasses / activates a number of effects)

### controlling
The guitarist usually likes to use a standard program control foot pedal, that has up and down switches and a display that shows the current program number.
- A more fancy controller is thinkable that shows the name of the program.
- An even more fancy that shows a visualisation of the chosen effect chain.

Note: i must be used on stage, where the lighting is difficult. It can be dark, there can be bright lights. In both circulstances it must be possible to view the current program.

### hardware architecture
A teensy, ESP32, RP pico or STM32 controller should be easily able to the job, I think.
Choices are about:
- screen: simple or advanced?
- link phone or tablet via WiFi or BT?
- Link computer in some way in order to setup?

The realtime program that is active on stage should be pretty straightforward:
- wait for program change
- switch new configuration

## 2 a simple speaker and amp switcher
This is rather like to above, but different things are switched.
An audio signal is routed to any of a number of (pre-)amplifiers
The pre-amp output (higher level audio) is routed to any of a number of power amplifiers
The power amp output (much higher level again) is routed to **one** of a number of speakers (one on one always)

The simple version only does the pre-amp to power amp switching. If not too complicated (too many amps), it can be done with relays as well. That will keep the audio pure as it is, no components inbetween. I know analog switch chips exist.

## 3 a much more complicated polyphonic modular synth controller, router, patch-saver and infrastructure
This is the most ambitious project.

The inputs are (can be) many and in many forms (voltage, CV, any other digital form)
The outputs are often CV (which may be delegated to breakout modules (e.g. eurorack) that receive digital signals in real time, and produce (via D/A conversion) analog CV signals to steer oscillators, VCA's, VCF's, analog ADSR's and any other module that is controllable by CV voltage / gate signals

The brain must be able to tune and calibrate oscillators, so receive some audio input and measure frequency.

There must be way, like the other two projects, to configure the hardware setup and then create, edit and save programs (patches). This is something that is normally not possible in modular synth setups, and it also allows to create polyphonic patches much more easily.

### typical poly synth setup
A typical polyphonic synthesizer may involve:
- 2 sets of 8 oscillators
- 4 sets of 8 VCA's
- a set of 8 filters
- 4 sets of 8 envelope signals (they may be digitally generated by the brain, but D/A'd by breakout modules)
- a number of LFO's that respond to control signal, e.g. envelopes, mod-wheels or velocity (they may also be generated by the brain, but could also be analog)
- a number of other modules to modulate the sound

### CV matrix
This creates the need for a CV matrix as well. I see 3 possible ways to do that:
1. just plain old wires. Disadvantage: patches cannot be saved and activated. Cables must be re-plugged. Setups can be saved as information (a picture, a graph) to help with re-setup a patch of course.
2. all analog, with a analog switch inbetween. Costly for polyphony, as the number of possible paths are rather big. Also long cable lengths, as eurorack setups can be big
3. all CV outs are digitised (A/D) and sent to the brain via a digital bus, CV-outs already existed, also controlled via the bus. The brain does the matrix. In code, this is not too difficult. Timing must be tight, with low latency, but it is not audio, but CV, which is much slower.

### audio matrix
This leaves the problem of the audio matrix though. Often the audio path stays the same, although CV's are routed differently.
1. Then a number of manual (cabled) setups can suffice (helped by images/graphs like with option 1 for CV matrices).
2. an analog switch may be good here, to make some routings possible without changing cables. Disadvantage: signal path goes to a chip and not only through a cable.

### solution, hardware architecture
The questions are:
- which hardware is able to function as the brain?
   - is a teensy (4.1 or 4.2) powerfull and fast enough? Extra AD and DA are needed, multiplexing too etc. But could it function as the brain?
   - can a Raspberry Pi do the job?
   - do we need a stronger computer to do this?

- how to communicate between the brain and the breakout boards (that gather CV (voltage or gate signals) and send out CV (same))
   - MIDI? -> probably too slow, latency, etc. MIDI over USB might be faster
   - SPI? -> proprietary protocol needed (within SPI), but it can be fast. In and out can be on the same line (bus), but can also be separated. Sending data is easier than collecting data.
   - CAN?
   - UTP?

   I feel for SPI, but am also not sure. CAN has been advised, but I am not sure it can handle all data and speed needed.

   UTP could be something too.
